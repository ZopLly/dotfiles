# План обновления рабочего стола

Статус: пользователь одобрил подготовку исправлений и дополнений. Применение
в рабочую сессию остаётся отдельным шагом после проверки. SSH-ключи не читать.

## Направление

Общая верхняя панель на Quickshell/QML: слева рабочие пространства и компактный
медиа-блок, по центру время/календарь, справа системные индикаторы и управление.
Кнопка и шторка должны быть одним визуальным элементом: расширение ширины и
высоты, затем появление содержимого. Продолжительность 250–350 мс, без сильного
отскока. Одновременно открыта одна панель; Esc, повторный клик и клик снаружи
закрывают её. Панели не должны сдвигать окна при раскрытии.

Центр: часы, дата, календарь с понедельника. События — только после выбора
пользователем источника календаря. Справа: Wi-Fi, Bluetooth, VPN, звук, яркость,
батарея, режим питания при поддержке системой, не беспокоить, блокировка и питание.
VPN: определить используемый клиент и поддерживаемый интерфейс, не читать
учётные данные или ключи. Не выдавать запуск приложения за подключение VPN.

Рабочий стол: необязательные часы/дата и медиакарточка на нижнем слое.
Экран блокировки: единый gtklock, общая палитра, часы/дата; дополнительные виджеты
оценить по возможностям установленной версии. Обычные desktop-виджеты не являются
заменой блокировщику.

## Этапы реализации

1. Изолировать ссылки и пути staging; исправить автозапуск обоев, хоткеи,
   единый вызов блокировки, восстановление сессии и установку компонентов.
2. Сделать единый источник палитры; исключить широкие sed-замены рабочего конфига.
3. Реализовать оболочку с реальными состояниями сервисов и уведомлениями об ошибках.
   Данные по событиям, частый опрос только для открытых панелей там, где необходим.
4. Проверить прототип на масштабе 1.6, раскрытие/закрытие, фокус, несколько экранов,
   полноэкранные приложения и реальные расходы CPU/RAM. Не обещать 230 МБ из референса.
5. Добавить виджеты рабочего стола и согласованное оформление gtklock.

Quickshell при исследовании не найден в PATH. Установка и запуск не выполнены.
Waybar/Eww сохранить как вариант отката на период перехода.

## Как использовать подготовленные изменения

Предусмотреть команды проверки, предварительного просмотра, применения и отката.
Их пока нет: не запускать старый install.sh из staging для тестирования.
Предварительный просмотр оболочки — отдельный экземпляр с отдельным конфигом,
без её добавления в автозапуск и без записи в рабочие конфиги. Для всей сессии
предпочтителен изолированный тестовый профиль; вложенная сессия должна исключать
рабочий автозапуск и действия над основной сессией.
После одобрения конкретного diff: резервная копия затронутых файлов и ссылок,
применение только выбранного набора, проверка и доступный откат. Не связывать
рабочие конфиги напрямую с изменяемой staging-копией.
