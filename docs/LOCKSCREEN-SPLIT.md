# Блокировка: вариант Б — применено

Пользователь выбрал композицию с часами слева и входом справа. Перенесено из макета в настоящий GTK-интерфейс gtklock 4. 22 октября 2026 применено по прямой команде пользователя, снимок `20261022-214203-integrated`. Проверены новая ссылка gtklock, все три собранных модуля и активный swayidle. Основная сессия для проверки не блокировалась.

- Крупные часы/дата слева, карточка входа с именем и монограммой справа; нейтральная подпись о заблокированном сеансе.
- Музыка и до трёх уведомлений размещаются в выделенном нижнем контейнере и не перекрывают вход. Батарея с процентами сверху справа. При отсутствии данных соответствующие элементы скрыты.
- Уже существующий выбор палитры и независимых обоев сохранён. CSS использует общие токены, проверены четыре исходные темы.
- Уже существующие GtkBuilder ID, сигналы проверки/показа пароля и секретность GtkEntry сохранены. PAM, код проверки пароля и ext-session-lock не изменялись.
- При ширине меньше 920 пикселей — вертикальная композиция. Модуль изменяет раскладку только при переходе через границу, иначе постоянный пересчёт мешал выделить размер поздно появившимся виджетам. Исправление защищено проверкой ненулевых размеров уведомлений/музыки/батареи.
- Полная подготовка релиза теперь переносит XML/CSS/источники и собирает minimal, notifications, layout. Точечный режим обновления приложений не переносит блокировку или дашборд.

## Проверки

1. XML: оригинальные ID, password input-purpose/visibility и обработчики входа.
2. Все три модуля собраны с предупреждениями как ошибками.
3. Реальный GtkBuilder + GTK/CSS + модули отображения в offscreen-окне: 1280×800, 1280×720, 760×1000. Три тестовых уведомления; проверки ориентации, правого выравнивания, размеров окна и дополнительных элементов. Отрисовка не читает личные службы: attach-функции создают только виджеты.
4. Настоящий gtklock захватил блокировку отдельного вложенного Niri; загружены все три модуля. Пароль не вводился, рабочая сессия не блокировалась.
5. Fake gtklock: одновременные запросы, готовность daemonize, фон, запуск по стабильной ссылке и распространение ошибки. Тесты отката выпуска также проходят.

Не проверены: реальная разблокировка пользователя, сон/пробуждение в основном сеансе, изменение масштаба/перенос между экранами после запуска уже заблокированного окна. Это нельзя считать проверенным только по изолированному запуску.
