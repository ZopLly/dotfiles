# Исправления перед обновлением оболочки

Подготовлены только в staging. Рабочая сессия не изменена.

## Сделано

- Относительные ссылки тем и пути конфигов в staging указывают на staging.
- Один механизм обоев: awww, ожидание готовности демона, обои выбранной темы.
- Блокировка на Super+Alt+L, единый gtklock для хоткея, Eww и swayidle.
- Ctrl+U/I теперь согласованы с направлением обычных U/I.
- Цвета Niri подключаются отдельным файлом. Смена темы предварительно проверяет
  конфиг и не переписывает его sed-заменами. Ошибки обновления компонентов видны.
- Существующие палитры сохранены, включая фиксированную палитру Mako. Fuzzel уже
  был связан с текущей темой: первоначальное предположение о фиксированной палитре
  Fuzzel оказалось неверным. Его ссылка сохранена и сделана относительной.
- Alacritty использует текущую тему, Eww импортирует существующий SCSS темы.
- Исправлены селекторы CSS и отсутствующее описание кнопки запуска Waybar.
- Опрос Eww приостановлен для закрытых панелей; исправлены пустые числовые значения
  позиции/длины трека, состояния раскрытия и адресация экземпляра Eww.
- Загрузка обложек имеет тайм-аут и атомарное сохранение; CAVA использует отдельный
  временный конфиг для каждого экземпляра и не убивает другие экземпляры.
- Сессия сохраняется атомарно, ID пространства преобразуется в имя или индекс.
  Старый ошибочный формат отклоняется. Это восстановление приложений и примерного
  размещения: вкладки браузера, документы, группы окон в колонках и точные координаты
  плавающих окон не восстанавливаются. Поддержаны прежние Alacritty, Firefox, Happ.
- Установщик по умолчанию только показывает план. Применение создаёт отдельную
  копию файлов, сохраняет прежние настройки и позволяет откатить ссылки.

## Палитра и внешний вид

Существующие файлы палитр не перекрашены. Дополнительные niri-runtime.kdl повторяют
цвета прежнего переключателя. Разница active/inactive, отключённая рамка Alacritty,
прозрачность, анимации и размеры панели оставлены до обсуждения дизайна.
Не добавлялись именованные рабочие пространства или новые правила размещения:
это выбор организации рабочего процесса, а не исправление ошибки.

## Проверка и применение

Без изменения сессии:

```sh
cd /home/andrew/dotfiles/niri-staging
python3 dev/tests/check_staging.py
./install.sh
```

После отдельной команды пользователя на применение:

```sh
./install.sh --apply
```

Установщик выводит путь к manifest.json для отката:

```sh
./install.sh --rollback /полный/путь/manifest.json --apply
```

Сервисы автоматически не перезапускаются. Для полного перехода потребуется
повторный вход в сессию; перед этим проверить зависимости и активацию swayidle.
Установка конфига Niri может быть замечена текущим Niri автоматически.
Не выполнять --apply для визуального предпросмотра.

## Зависимости и ограничения проверки

Основные команды: niri, python3, bash, jq, waybar, eww, alacritty, fuzzel,
mako, gtklock, swayidle, awww, awww-daemon, magick, playerctl, wpctl, pamixer,
brightnessctl, cava, curl, notify-send, gsettings, pavucontrol, gsimplecal,
nm-connection-editor, blueman-manager; шрифт JetBrainsMono Nerd Font.

Автотесты используют временные HOME/XDG-каталоги и подставные команды для смены
темы; реальные сеть, звук, блокировка и демоны не затрагиваются.
Проверены установка/откат, все темы Niri, shell-синтаксис, ID пространств и смена
тем без изменения основного конфига. Eww/Waybar визуально не запускались:
фокус, закрытие по фону, стили и блокировку следует проверить в тестовой сессии.

## Дополнительная проверка установки

- Обои берутся исключительно из текущей темы рабочего стола. Скрипт ожидает
  не только сокет awww, но и регистрацию экрана. Картинка локскрина не подставляется.
- Предпросмотр проверен снимком пустого рабочего пространства: GIF-обои видны.
- Устанавливаются только Alacritty, Waybar, Eww, Fuzzel, Mako, gtklock, Niri
  и файл swayidle.service. Настройки Kitty, GTK и swaylock не заменяются.
- Нужные команды проверяются до применения. На момент проверки все найдены.
- Конфиг Niri подключается последним, после остальных компонентов.
- Отдельная подготовка установочной копии, без подключения к рабочим настройкам:

```sh
./install.sh --stage-only
```

- Проверены сохранность файлов тем, отсутствие демонстрационных элементов в
  установочной копии, установка и откат, а также автоматическое восстановление
  после искусственного сбоя посреди установки.

После самостоятельного применения `./install.sh --apply` установщик выдаст путь
к резервной копии. Перед следующим входом в сессию обновить описание сервисов:

```sh
systemctl --user daemon-reload
systemctl --user enable swayidle.service
```

Это не перезапускает текущий swayidle. Полностью новый набор фоновых процессов
запустится после выхода и повторного входа. До этого возможна смесь старых
процессов и новых конфигов; установка не является визуальным предпросмотром.
Проверка блокировки и сна на реальном экране ещё требует отдельного испытания:
вложенный предпросмотр намеренно не управляет ими.
